# The agent edits the original in place, holding the lock for one operation

The agent edits the document the user named — not a persistent working copy —
so there is never a question about which file is real. But it holds the file
open only for the length of a single operation: open, edit, save, close,
measured at **228 ms** against a warm hidden instance. Between operations the
file is entirely free.

The obvious alternative was to keep the document open for the session and let
Word arbitrate access. We measured that and it does not work. Word does not
arbitrate, it *blocks*: while a hidden instance holds a document, every external
write pattern a generator uses fails with a sharing violation, and a second Word
opening the same path hangs indefinitely — with `DisplayAlerts` already off, so
nothing surfaces a dialog anyone could dismiss. Both processes had to be killed
externally. An A/B control isolates the lock as the cause, since the same second
instance opens a *different* file in 1167 ms.

Holding the file would also have broken the feature the viewer was built
around. Auto-refresh exists so that a document regenerated by a script updates
in the canvas; if we hold the original open, the script's write fails before
the watcher has anything to observe.

## Consequences

Every operation must first test whether the file is already open, by attempting
to take a write handle — 4 ms when held, 9 ms when free, correct in both
directions. Detection must not be done by trying to open the document in Word,
because that is precisely the call that hangs.

Detection and open are not atomic, so a fast reject is not a guarantee. Every
`Documents.Open` must additionally be bounded by a timeout and the instance
abandoned and killed if exceeded. Treat an unbounded open as a defect.

This is affordable only because rendering is decoupled — the canvas displays an
exported PDF, so nothing needs the document open to keep the display alive —
and because undo is a per-operation snapshot rather than Word's in-process undo
stack, which does not survive the close.
